# План разработки: ansible-readme-gen v2

## Цель
Создание кроссплатформенного инструмента (бинарник, Docker, Homebrew) для генерации документации Ansible с расширенным функционалом.

---

## Ключевые требования и новые возможности

1.  **Дистрибуция**:
    *   Сборка в единый бинарный файл для Linux/macOS (*PyInstaller*).
    *   Формула для установки через *Homebrew*.
    *   Образ *Dockerfile* для запуска в CI/CD или без локальной установки зависимостей.

2.  **Логика работы**:
    *   Автоматическое определение типа входных данных: роль (*role*) или плейбук (*playbook*).
    *   Генерация сводки (*summary*) на основе полей `name:` задач.
    *   Сохранение существующей логики парсинга аннотаций (`@`).

3.  **Интерфейс (CLI)**:
    *   Использование библиотеки *click* для построения CLI.
    *   Новые флаги:
        *   `--output (-o)`: путь сохранения файла.
        *   `--check`: режим проверки (вывод диффа), полезен для CI.
        *   `--template (-t)`: кастомный шаблон Jinja2.
        *   `--no-task-names`: отключить сбор описаний из названий задач.
        *   `--exclude-tasks`: исключить задачи по паттерну.
        *   `--type`: принудительно задать тип (роль/плейбук).

## Архитектура проекта

### Структура каталогов

```
ansible-readme-gen/
├── .gitignore
├── README.md
├── pyproject.toml          # Зависимости, скрипты сборки (build, lint, test)
├── LICENSE
├── Makefile                # Удобные команды для разработчика
├── dist/                   # Директория для собранных бинарников
│
├── ansible_readme_gen/     # Основной пакет приложения
│   ├── __init__.py
│   ├── cli.py              # Точка входа, парсер аргументов (Click)
│   ├── core.py             # Оркестратор: main(), обработка ошибок
│   ├── collector.py        # Парсинг YAML, извлечение метаданных, task names, @-блоков
│   ├── models.py           # Dataclasses: RoleInfo, PlaybookInfo, TaskDoc, VariableDoc
│   ├── generator.py        # Логика сборки финальной строки README
│   ├── renderer.py         # Jinja2 рендеринг + логика вставки между маркерами BEGIN/END
│   └── templates/
│       └── readme.j2       # Дефолтный Markdown-шаблон
│
└── tests/                  # Тесты
    ├── __init__.py
    ├── fixtures/           # Примеры ролей/плейбуков для тестов
    │   ├── simple_role/
    │   └── complex_playbook.yml
    ├── test_collector.py
    ├── test_generator.py
    └── test_cli.py
```

### Описание модулей

*   **cli.py**: Полная ответственность за интерфейс командной строки. Преобразует аргументы в объект `Options`. Запускает конвейер через `core.run(options)`.
*   **collector.py**: "Грязная" работа с файлами. Читает файловую систему, использует PyYAML. Возвращает структурированные модели из `models.py`. Не должен ничего знать о шаблонах.
*   **models.py**: Чистые Python-классы (*Pydantic/Dataclasses*). Единый язык данных внутри всего приложения.
*   **generator.py**: Принимает модели, строит промежуточную структуру данных для шаблона. Содержит бизнес-логику ("если нет описания в @, но есть name, использовать его").
*   **renderer.py**: Низкоуровневая работа с текстом. Загружает Jinja2, применяет шаблон. Отвечает за поиск маркеров `<!-- BEGIN ... -->` и замену блока.
*   **core.py**: Связующее звено. Вызывает коллектор -> генератор -> рендерер. Обрабатывает исключения и запись в файл.
